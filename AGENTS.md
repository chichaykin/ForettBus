# AGENTS.md

## Project

Flutter-приложение Forett Shuttle для расписания автобусов Forett ↔ Beauty World.
Package ID: `com.forett.shuttle_bus`.
Основная платформа проверки: Android Pixel.

## Source of truth

- `lib/schedule.dart` — расписание и часовой пояс.
- `lib/notifications.dart` — уведомления и exact alarms.
- `lib/bus_arrivals.dart` — клиент live ETA и статический fallback 41/77.
- `lib/screens/` — экраны приложения.
- `lib/main.dart` — тема, навигация и глобальное состояние.
- `lib/app_settings.dart` — сохранение темы и основного направления (`app_settings.v1`).
- `lib/trip_cards.dart` — модели и сохранение карточек (`trip_cards.v1`), нормализация номеров автобусов.
- `lib/trip_planning.dart` — поиск OneMap и разбор автобусных/пеших участков.
- `lib/trip_forecast.dart` — выбор доступных прогнозов с учётом подхода и пересадок.
- `lib/widgets/trip_card_view.dart` — компактная карточка поездки и раскрываемые подробности.
- `android/app/src/main/AndroidManifest.xml` — Android permissions, receivers и launcher icon.
- `IMPROVEMENT_PLAN.md` — актуальный аудит проекта и порядок следующих улучшений.

## Live bus arrivals

- Flutter обращается только к HTTPS Cloudflare Worker из `worker/`; LTA AccountKey не должен попадать в приложение или Git.
- Клиентский `APP_API_KEY` передаётся только через `--dart-define-from-file=.bus_api.env`; файл `.bus_api.env` не коммитить.
- Worker должен проверять Bearer-ключ до чтения cache и до обращения к LTA/OneMap.
- Сохранять совместимость `/v1/arrivals?direction=...`: `Direction`, остановки `42221`/`42151`, маршруты 41/77.
- Пользовательские карточки используют `/v1/arrivals?stopCode=...` с пятизначным кодом. Без `services` сервер возвращает все линии остановки; клиент выбирает сохранённые номера.
- Дополнительные защищённые endpoint: `/v1/stops/search` (места OneMap), `/v1/stops` (остановки LTA), `/v1/trips/plan` (автобусные варианты OneMap).
- `ONEMAP_TOKEN` хранить только в секретах Worker. Это истекающий access token; не утверждать, что автообновление реализовано, пока нет серверной логики и учётных данных.
- Не подключать платные API или автоматический переход на платные тарифы.
- При ошибке live API сохранять fallback 41/77 только для поддерживаемых выше остановок с пометкой `Scheduled`. Для остальных остановок не создавать вымышленное расписание. Не показывать внутренние ошибки Worker/LTA.
- Опрос ETA запускать только на активной Home-вкладке и при активном приложении; сохранять интервал не чаще 20 секунд.
- Live ETA городских автобусов означает прогноз прибытия на остановку посадки; он не является временем отправления шатла.
- Успешные ответы Worker могут быть закэшированы на 20 секунд; данные старше 60 секунд приложение должно считать неактуальными.

## Notifications

- Сохранять idempotent initialization `NotificationService`.
- Активное напоминание публикуется через `NotificationService.activeReminder`; Home и Profile должны подписываться на это общее состояние, а не поддерживать независимые копии.
- При изменении notification logic сохранять возможность повторной инициализации после ошибки и проверять, что активное напоминание обновляется после schedule/cancel/restore.
- Не удалять `POST_NOTIFICATIONS`, `SCHEDULE_EXACT_ALARM` и notification receivers.
- После изменения notification logic проверять permissions на реальном Android-устройстве.
- После запуска integration-тестов обязательно заново выполнить обычный `flutter build apk --debug`, потому что integration test может заменить debug APK тестовым entrypoint.

## UI behavior

- Direction toggles должны менять расписание и ближайший автобус.
- Карточка шатла на Home называется `Forett Shuttle`.
- Для работающего шатла показывать countdown до следующего отправления с обновлением каждую секунду и сохранять точное время `Departs at HH:mm`.
- Время шатла — время отправления с начальной остановки выбранного направления, а не время прибытия.
- После последнего рейса показывать `Service ended` и `The last shuttle has departed`; в воскресенье показывать `No shuttle today`.
- Карточка `Public buses` остаётся независимой от расписания шатла и показывает маршруты 41/77 с ETA до остановки посадки.
- Dark Mode должен менять тему всего приложения и вместе с основным направлением восстанавливаться до первого кадра при запуске.
- Исходный блок переключателей, `Forett Shuttle` и `Public buses` остаётся первым. Пользовательские карточки идут ниже и имеют независимые направления и порядок.
- Переключатель поездки использует короткое имя карточки (`To Grab HQ`), адрес/индекс хранится отдельно. Не показывать `Origin`/`Destination` вместо названия места.
- В свернутой карточке показывать первый автобус, остановку посадки и цепочку номеров; подробности раскрываются через `Route details`. Пересадка — смена автобуса; начальный/конечный пеший участок не является пересадкой.
- Нормализовать `TTS BUS 963`/`SBST BUS 166` до `963`/`166` при импорте и чтении старых карточек. Приоритет в OneMap — `routeId`; для LTA хранить `stopCode`, удалять префикс `FERRY:` у `stopId`.
- Сохранять длительность каждого участка после выбора маршрута и Save. При ручном изменении участка сбрасывать его старую длительность. Изменение имени не должно стирать длительность.
- Первый прогноз выбирать после пешего подхода; пересадку — после длительности предыдущего участка, перехода и запаса 2 минуты. Среди альтернатив выбирать самый ранний подходящий автобус.
- При неизвестной длительности показывать только прогноз на остановке, без обещания успеть. Не прибавлять полную длительность плана к первому ETA: это повторно учитывает подход/ожидание. Время прибытия в пункт назначения выводить только при достаточных данных по всей цепочке.
- Объединять запросы одинаковых остановок и ограничивать их интервалом 20 секунд, в том числе при переключении направления. Возраст считать по серверному `fetchedAt`; после 60 секунд не показывать устаревший прогноз как Live.
- После редактирования/удаления/смены направления инвалидировать старые ответы. Ошибка одной остановки не должна стирать доступные данные остальных.
- Не обозначать весь блок как Live, если все прогнозы имеют `monitored=false`. Различать `Live`, `Scheduled` и расчётное время `Estimated`.
- Сохранённые маршруты не менять автоматически; поиск других вариантов — явное действие `Find alternatives` в редакторе с последующим Save.
- После каждого `await` в StatefulWidget проверять `mounted`.
- Контакты на Profile должны оставаться видимыми и интерактивными.

## Validation

Перед коммитом запускать:

```bash
dart format --output=none --set-exit-if-changed lib test integration_test
flutter analyze
flutter test
flutter test integration_test/app_test.dart -d <device-id> --no-uninstall
cd worker && npm ci && npm test && npm run typecheck
```

Для проверки на Android:

```bash
flutter build apk --debug --dart-define-from-file=.bus_api.env
adb -s <device-id> install -r build/app/outputs/flutter-apk/app-debug.apk
adb -s <device-id> shell monkey \
  -p com.forett.shuttle_bus \
  -c android.intent.category.LAUNCHER 1
```

После изменений мобильного UI проверять приложение визуально на устройстве.
- Проверять новую карточку на узком экране и с увеличенным шрифтом, а на Pixel — в светлой и тёмной темах. Не оставлять тестовые карточки/прогнозы в данных пользователя.
- До integration-тестов сохранять локальную резервную копию настроек устройства. Тесты должны использовать mock preferences и не менять реальные карточки/тему. Всегда передавать `--no-uninstall`: по умолчанию `flutter test` удаляет приложение после интеграционного прогона.
- Для обновления приложения использовать `adb install -r`, а не `flutter install`: последний в текущей версии Flutter удаляет старую установку. Не удалять приложение/данные ради проверки.
- Последняя проверенная конфигурация: Pixel 8 Pro, Android package `com.forett.shuttle_bus`.
- После integration-тестов устанавливать именно обычную сборку, собранную с `.bus_api.env`, чтобы на устройстве остался рабочий live API, а не тестовый entrypoint.

Для сохранения снимков Pixel на компьютере:

```bash
flutter drive --driver=test_driver/integration_test.dart \
  --target=integration_test/app_test.dart -d <device-id>
```

Снимки сохраняются в игнорируемую Git папку `build/review/`. После этого также восстановить обычный debug APK.
